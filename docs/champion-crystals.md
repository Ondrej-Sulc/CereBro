# Champion crystal pools

Crystal pool membership is a recorded possible reward at an exact champion star level. It is separate from drop rates, current store availability, ownership and the champion's obtainable rarity list. An absent record does not prove that a champion is unobtainable.

The parallel follow-up investigations are [crystal drop rates and opening rules](crystal-drop-rates-investigation.md), [champion ascension and materials](champion-ascension-investigation.md), and the [application integration audit](acquisition-ascension-integration-audit.md). [Evidence boundaries](crystal-ascension-source-boundaries.md) describe what the primary sources establish. Reusable `extract_mcoc_crystal_rules.py` and `extract_mcoc_ascension.py` now preserve exact source-specific mechanics and upgrade requirements as separate investigation artifacts. They do not add numeric odds to this champion-membership catalog or silently refresh its source snapshot.

The normalized snapshot lives in `src/data/game-crystals/catalog.json`. This is shared read-only catalog data; no database migration or production database import is required. `src/data/game-crystals/index.ts` provides `getChampionCrystals(gameId)` for full projections and `getChampionCrystalSummary(gameId)` for main pools and archive counts. Consumers can also use `createCrystalCatalog(snapshot, publishedArtworkManifest)` directly.

## Source and verified joins

The 3 November 2026 cache contains 2,437 crystal definitions, including 2,112 with direct champion rewards, 3,284 reward categories and 1,864 referenced blueprint identities. The source contains 33,422 ordinary hero reward entries and 66 hero-with-cosmetic (`hcos`) entries before deduplication. Old event definitions remain in the cache; every crystal's `EndTime` was -1, so it cannot establish live sale dates.

Named current protobuf contracts and the game's `GachaBox.PossiblePrizes` lookup establish:

1. `GachaDataBuffer.groups → GachaGroup.Set → GachaSet.Boxes` supplies crystal definitions.
2. `GachaBox.Name` (field 28) is identity; `_displayName.en` (field 30, then LocText field 1) is the English label. `Token` is separate.
3. `_possiblePrizeCategories` (field 42) references `GachaCategory.Name`; `PossiblePrizes` expands those categories' `Items`.
4. Direct champion rewards use `RedeemerItem.Type == "hero"` with an exact blueprint `Data`, or the verified `hcos` form `Data == "<blueprint>|first_edition"`. The blueprint joins to `BCGBlueprintBase.Blueprint`, then `Character` (the database's `Champion.gameId`) and `Rarity` (actual 1–7 stars). No English-name or star-suffix inference is used. Cosmetic entries retain the original `Data`, cosmetic identity and exact tier binding in `heroCosmeticRewards`; reader projections retain the matching rarity.

Carousel categories, carousel featured prizes and box featured prizes are display previews and are excluded from reward membership. `_boxFeaturedPrizes` (field 44) is separately joined through the same verified hero/hcos blueprint identities into `promotedChampionIds` for editorial browsing classification only. Star variants of one promoted champion are deduplicated. This does not add a champion to the possible reward pool or establish increased odds. Shards, nested crystals, pity/bonus rewards and reviewed non-champion item types are not expanded into champion membership. Reward type counts remain in coverage. Unknown reward types and unverified hcos cosmetics now stop extraction for review. Hero quantities/actions are validated; context metadata such as bonus-reward pointers does not add another champion.

The hcos correction recovered Gwenom's 7-star rewards in `pfh_gwenom_en_pointe_crystal` (En-Pointe Grace Crystal) and `vfh_gwenom_broken_justice_crystal` (Broken Justice Grace Crystal). A source-to-reader audit recovered 63 champion/crystal/star relationships across 53 champions and 23 definitions, while preserving all 722,627 existing relationships. Two definitions previously containing only hcos rewards enter browsing for the first time. This is an extraction correction to the same captured source, not a new game snapshot. Existing artwork references and hosting are unchanged. Crystal contents label First Edition possibilities only at the matching star level.

The snapshot preserves source crystal IDs, group/set identities, category IDs, blueprint IDs, selection counts and both artwork references. Equivalent source aliases share a flat display entry only when name, all category identities, selection mode, primary/banner artwork and main/other classification agree. Original source IDs remain available.

On champion pages, other recorded crystals open and load automatically when the selected star level has no main pools. When main pools exist, the archive remains collapsed until requested. Users can collapse an automatically opened archive; empty archives are not fetched.

## Artwork source and hosting

Primary art uses `_closedImage.en` and `ClosedOnCDN`, with `_tokenImage.en` as a fallback only when closed art is empty. Banner art uses `_backgroundImage.en` (field 34) and `BackgroundOnCDN` (field 13). These are the champion montage images on the left of in-game crystal cards; the Titan source was visually verified against the supplied game screenshot. `GameSpecificData.HologramImage` is a different asset and is excluded. Banners are promotional artwork, not evidence of full reward membership; exact contents continue to come from the reward categories.

`extract_mcoc_crystal_artwork.py` resolves packaged images by full logical resource path. Cached CDN images use SHA-1 of the absolute URI path (leading slash included), uppercase, plus the extension, matching `EB.Cache.GetCacheFilename`/`GetCacheFileNoCdn`. Missing files can be fetched by exact reference from the public host embedded in game metadata, `https://kabam-marvel.shared.mcoc-cdn.net/`. An opposite transport flag is recovered only when another definition independently binds the identical reference to the verified resource/CDN transport. No account, cookie or authenticated game API is used.

The extraction resolves 707 primary and 1,676 banner bindings, deduplicated into 2,015 role-specific images (431 primary, 1,584 banners). Lossless WebP preserves source pixels and transparency. All main pools have both forms of artwork. Primary icons cover 2,111 of 2,112 direct-champion definitions; the missing resource `uigacha/crystals/crystal_uncommon` belongs to the tutorial `fte_random` definition and retains a neutral fallback. Banners cover 2,109 direct-champion definitions: two have no source banner and the 24 MB, 7,316-pixel-wide `sinister_six_box` background exceeds the export limits. Missing artwork is not substituted with a hologram or inferred from the name.

Local extraction files and manifests remain under ignored `temp/crystals/`. They are not bundled in `web/public`. The website and bot use the same Google Cloud Storage bucket/configuration as champion and relic images: `GOOGLE_CREDENTIALS_JSON`, `GCS_BUCKET_NAME` (default `champion-images`) and `gcpStorageService.uploadImmutableBuffer`.

Objects are named `crystals/primary/<sha256>.webp` and `crystals/banner/<sha256>.webp`, with `public, max-age=31536000, immutable` caching and create-only uploads. Existing objects are reused only if bytes agree. `crystalArtworkService` validates local hashes, deduplicates uploads and fetches every public cloud object to check its bytes. The CLI checks source bindings against the catalog before uploading and atomically writes the published `artwork.json` only after all objects verify. Failed uploads leave the previous application manifest intact. Retrying safely reuses matching cloud objects. Previously published hologram objects are left untouched but are no longer referenced.

The published version-3 manifest contains cloud URLs, explicit primary/banner role/reference bindings, input/output hashes, dimensions, origins, bucket and source hashes. The reader validates bucket/object paths, complete binding accounting and the matching gacha snapshot. Runtime reads need no Google credentials. Next Image supplies responsive thumbnails and cached browser-format optimization, as for champion and relic portraits.
