# Reproducing historical node snapshots

The reviewed v1 node icon registry and icon-binding JSON were written on
Windows by `project_mcoc_node_icon_registry.py`, whose `Path.write_text` calls
use the platform default newline. Their frozen bytes therefore contain CRLF.
The registry, bindings, historical producer and source-index hashes stay fixed.

`test_project_mcoc_node_icon_registry.py` runs the unmodified producer inside
`historical_text_output.historical_crlf_output(output_root)`. This explicitly
replays the original default text serialization on every host. It applies only
to writable text files opened through pathlib inside that temporary output
root. Inputs, binary outputs, explicit newline choices and outside paths are
unaffected, and the writer is restored even after failure. This context is for
serial offline replay, not concurrent application code.

The test still compares every generated byte against the historical files.
Nothing is normalized after generation, so any hashes computed by a producer
refer to the bytes actually written. Scope, explicit-newline, Linux-default
and restoration regressions run in the same named CI suite.

The other six explicit node Python suites verify source content, geometry,
source-index pins and behavior without regenerating this historical registry.
Do not edit their frozen producer files simply to change serialization: those
files themselves are part of the recorded source proof.
